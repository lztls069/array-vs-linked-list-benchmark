# 实验一 数组与链表性能对比实验

用 C 语言分别实现**顺序表（动态数组）**与**单链表**两种线性存储结构，存储同一批随机生成的学生数据，在 5 组不同数据规模下测量**创建、查询、插入、删除**四类操作的耗时，并对比两种结构的性能差异。

## 一、实验要求

| 项目 | 要求 |
| --- | --- |
| 数据项 | 学生信息：姓名、年龄（15~40）、成绩（0~100） |
| 数据规模 | 100、1000、10000、100000、1000000 共 5 组 |
| 基本操作 | 创建、按姓名查询、指定位置插入、指定位置删除 |
| 计时方式 | 记录操作总耗时，单次操作耗时取平均 |
| 输出 | 各规模下两种结构的创建时间、查询/插入/删除平均时间表格 |

## 三、核心设计

### 1. 统一的线性表接口

`linear_list.h` 定义了一张函数指针表 `ListOps`，把两种结构的多态操作统一起来：

```c
typedef struct {
    void (*build)(void* self, const Student* data, int n);   // 创建
    int  (*find_by_name)(void* self, const char* name);      // 按姓名查询
    int  (*insert_at)(void* self, int pos, const Student* stu);
    int  (*remove_at)(void* self, int pos);
    int  (*size)(void* self);
    void (*destroy)(void* self);
} ListOps;
```

`seq_list_ops()` 与 `linked_list_ops()` 分别返回各自实现的实例，测试框架 `run_benchmark()` 只依赖 `ListOps`，因此两种结构走的是**完全相同的测试代码路径**，避免代码差异带来的误差。

### 2. 存储结构实现要点

- **顺序表**：`Student* data` + `size` + `capacity`，容量不足时按 2 倍扩容，插入/删除需要搬移元素。
- **单链表**：带**头结点（哑结点）**，使“在 0 号位置插入/删除”与中间位置的处理方式完全一致；另设**尾指针**，使创建时无需每次遍历到表尾。

### 3. 保证测试公平的手段

- **同一批数据**：每个规模只生成一次学生数据，两种结构共用。
- **同一组操作序列**：查询下标、插入位置、删除位置都**在计时前一次性生成**，两种结构面对完全相同的随机操作序列。
- **自定义随机数**：使用 xorshift32 而非 `rand()`（Windows 下 `RAND_MAX` 仅 32767，取大表随机下标时会严重破坏随机性）。
- **多次重复取平均**：每种规模重复若干轮（小规模 5 轮、大规模 1 轮），结果取平均以降低抖动。
- **防止优化**：用 `volatile` 累加查询结果，避免编译器把无效的查询调用优化掉。
- **高精度计时**：使用 `QueryPerformanceCounter()` 计时，单位为微秒。

## 五、测试结果

| Scale | Struct | Create(us) | Query(us) | Insert(us) | Delete(us) |
| ---: | :--- | ---: | ---: | ---: | ---: |
| 100 | Array | 0.26 | 0.05 | 0.04 | 0.04 |
| 100 | Linked | 3.18 | 0.06 | 0.09 | 0.07 |
| 1000 | Array | 12.58 | 0.35 | 0.22 | 0.19 |
| 1000 | Linked | 44.10 | 0.51 | 0.53 | 0.49 |
| 10000 | Array | 104.87 | 4.08 | 2.41 | 2.40 |
| 10000 | Linked | 457.47 | 16.09 | 16.48 | 16.87 |
| 100000 | Array | 1402.25 | 40.17 | 58.83 | 22.41 |
| 100000 | Linked | 4354.40 | 230.56 | 198.53 | 249.12 |
| 1000000 | Array | 20932.00 | 1768.30 | 2295.35 | 1379.18 |
| 1000000 | Linked | 49979.60 | 15929.13 | 21927.47 | 14306.06 |

其中 `Create` 为该规模下建表的**总耗时**，`Query / Insert / Delete` 为**单次操作的平均耗时**。

## 六、结果分析

1. **创建（Create）**：链表耗时约为顺序表的 2～10 倍。顺序表一次性分配内存并整体拷贝（连续内存，缓存友好）；链表需要为每个结点单独 `malloc`，除了数据拷贝还有分配器开销和随机内存访问。规模越大，差距越明显。

2. **查询（Query）**：两者都是 O(n) 顺序查找，但顺序表平均快 5～9 倍。链表每访问一个结点都要跟随指针跳转，缓存命中率低；顺序表是连续内存，能充分利用 CPU 缓存与预取。这说明**同样时间复杂度的算法，实际性能仍可能相差一个数量级**。

3. **插入（Insert）**：顺序表插入需要搬移 `pos` 之后的全部元素，理论 O(n)；链表只需改指针。但在**随机位置**插入时，链表仍要先 O(n) 遍历到 `pos-1`，且遍历开销（指针跳转、缓存不命中）远大于顺序表搬移连续内存的开销，所以实测中顺序表反而更快。

4. **删除（Delete）**：与插入同理。链表需要遍历定位前驱结点，实测仍慢于顺序表，规模越大差距越明显（100 万条时约 10 倍）。

5. **规模增长趋势**：顺序表各操作耗时随规模近似线性增长；链表由于指针跳转带来的缓存不命中，增长更快——查询从 1000 条的 0.51us 增至 100 万条的 15929us（约 3 万倍），远超数据规模增长的 1000 倍。

## 七、实验结论

- 两种结构的基本操作时间复杂度相同（查询/随机插入/随机删除均为 O(n)），但**常数因子差异巨大**。
- 顺序表的优势来自**内存连续**：缓存友好、无额外指针开销、无逐个分配/释放成本。
- 链表的理论优势在于“已知前驱结点时插入删除为 O(1)”以及容量动态增长；本实验的插入删除位置随机，链表必须先遍历定位，因此无法体现这一优势。
- 选型建议：以随机访问和遍历为主时优先使用数组/顺序表；若插入删除集中在已知位置（如表头、或已持有结点指针），且元素很大、搬移代价高时，链表才有价值。

## 八、可改进方向

- 增加“头部插入/头部删除”场景，展示链表 O(1) 的优势。
- 顺序表改为更平滑的扩容策略，或使用内存池优化链表结点分配。
- 引入 `std::vector` / `std::list`、跳表或哈希表作为对照组。
